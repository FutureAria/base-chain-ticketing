# 기술 선택의 근거

**왜 그 기술을 썼는가**를 적습니다. 최신이어서 고른 것과, 문제 때문에 고른 것을 구분합니다.
결정을 되돌릴 때 이 문서를 먼저 읽고, 여기 적힌 이유가 아직 유효한지 확인하세요.

---

## 1. 좌석 재고를 블록체인에 두지 않았다

**선택** — 좌석 점유의 단일 기준은 MySQL. 블록체인은 발급 증명과 이력만 담당.

**대안** — 좌석 상태 자체를 온체인/체인코드에 두는 방식.

**왜 안 썼나** — "지금 이 좌석이 팔렸는가"는 **밀리초 단위로 확정돼야 하는 질문**입니다.
온체인 확인은 블록 생성 시간만큼 걸리고, Fabric 도 합의 왕복이 필요합니다.
그동안 좌석이 "떠 있는" 시간이 생기고, 그 틈에 두 번째 결제가 들어오면 이중 예매입니다.

블록체인이 잘하는 것은 **되돌릴 수 없는 기록**이지, **경합 제어**가 아닙니다.
경합 제어는 DB 트랜잭션과 유니크 제약이 수십 년째 잘 해 온 일입니다.

**대가** — "티켓 소유권의 진실"이 두 곳(DB · 체인)에 나뉩니다.
그래서 상태 흐름을 맞추는 데 프로젝트의 무게를 실었습니다.

---

## 2. 좌석 잠금을 코드가 아니라 DB 생성 컬럼에 넣었다

**선택** — MySQL `GENERATED ALWAYS AS ... STORED` 컬럼 + `UNIQUE KEY`.

```sql
seat_lock GENERATED ALWAYS AS (
  CASE WHEN status IN ('refunded','cancelled') THEN NULL
       ELSE CONCAT(game_id,'|',block,'|',row_num,'|',seat_number) END
) STORED
```

**대안** — 서비스 코드에서 좌석 중복을 검사하고, 환불 시 좌석을 반환하는 로직을 작성.

**왜 이걸 골랐나** — 세 가지 때문입니다.

1. **검사와 삽입 사이의 틈을 코드로는 못 없앤다.** 락을 걸어도 경로가 하나 늘면 다시 뚫립니다.
2. **"환불하면 좌석 반환"을 아무 데도 안 써도 된다.** 상태만 바꾸면 컬럼 정의로부터 따라옵니다.
   반환을 빠뜨릴 코드 경로 자체가 존재하지 않습니다.
3. **UNIQUE 가 NULL 을 중복으로 보지 않는다**는 SQL 표준 동작이 정확히 필요한 의미론입니다.

**대가** — MySQL/MariaDB 에 묶입니다. 다른 DB로 옮기려면 같은 성질을 다시 만들어야 합니다.
이 프로젝트에서는 옮길 계획이 없어 받아들였습니다.

## 3. 실결제·온체인 민팅을 기본값에서 껐다

**선택** — `TOSS_MODE=mock` · `FABRIC_MODE=mock` · `ENABLE_ONCHAIN_MINTING=false` 가 기본.

**왜** — 두 가지 목적이 겹칩니다.

- **안전** — 실수로 실행해도 실제 돈이 나가거나 가스비가 발생하지 않습니다.
  실결제 모드에서 mock 으로 빠지는 우회 경로가 없는지 테스트(`tossMockGuard`, 5개)가 검사합니다.
- **기여 진입장벽** — 기여자가 Fabric 네트워크·테스트넷 지갑·PG 계약 없이 전 기능을 돌려볼 수 있습니다.
  진입 요건이 "Node + MySQL"로 내려갑니다.

**규칙** — mock 과 real 은 **같은 인터페이스**를 지킵니다. 한쪽에만 함수를 추가하면
모드를 바꾸는 순간 터집니다.

## 4. QR 을 회전시켰다 (정적 QR 대신)

**선택** — `HMAC-SHA256(QR_SECRET, "ticketId:슬롯")`, 슬롯 기본 10초.

**대안** — 티켓당 고정 QR, 또는 온체인 조회 기반 검증.

**왜** — 고정 QR 은 **캡처 한 장으로 복제**됩니다. 종이 티켓과 다를 게 없습니다.
온체인 조회는 검표 줄에서 쓰기엔 느립니다.

HMAC 은 서버에서 즉시 계산되고, 캡처본은 다음 슬롯에서 무효가 됩니다.
검표 시 **현재 슬롯과 직전 슬롯**을 함께 대조해 경계에서 실패하지 않게 했습니다.

**대가** — 오프라인 검표가 안 됩니다. 검표기가 서버에 붙어 있어야 합니다.

---

## 5. 결제 금액을 서버가 다시 계산한다

**선택** — 클라이언트가 보낸 금액은 **검증용**으로만 쓰고, 승인 금액은
`server/config/seatPricing.js` 에서 재계산.

**왜** — 클라이언트 값을 그대로 승인하면 금액 조작이 열립니다. 가장 흔한 결제 취약점입니다.

**부수 효과** — 가격표가 프론트(`app/data/ticketing.ts`)와 서버 두 벌이 됩니다.
어긋나면 테스트 `seatPricing`(10개)이 **깨집니다.** 불편하지만 의도된 것입니다 —
조용히 어긋나는 것보다 시끄럽게 깨지는 편이 낫습니다.

## 6. ERC-721 과 ERC-1155 를 나눠 썼다

| 대상 | 표준 | 왜 |
|---|---|---|
| 입장권 (`TicketNFT`) | ERC-721 | 좌석 하나에 티켓 하나. **개별 식별**이 본질 |
| 조각·박스 (`FragmentNFT` · `BoxNFT`) | ERC-1155 | 같은 종류를 여러 개 보유. **수량**이 본질 |

조각까지 ERC-721 로 만들면 조각 100개에 토큰 100개가 생겨 가스비와 조회 비용이 불필요하게 커집니다.

**공통 접근제어** — 네 컨트랙트 모두 `Ownable` + `setMinter(address,bool)` 구조입니다.
소유자만 민터를 지정하고, 민터가 아니면 발행·소각·입장 처리를 할 수 없습니다.
`TicketMarketplace` 는 `ReentrancyGuard` 를 함께 적용했습니다.

## 7. Fabric 과 Ethereum 을 둘 다 썼다

역할이 다릅니다.

| | 담당 | 왜 이쪽인가 |
|---|---|---|
| **Ethereum** | NFT 입장권 소유권·재판매 정산 | **공개 검증**이 필요하다. 지갑으로 소유를 증명하고, 외부 마켓과 호환된다 |
| **Fabric** | 포인트·멤버십·응모 원장 | **비공개 + 권한 제어**가 필요하다. 적립 이력을 전 세계에 공개할 이유가 없고, MSP 로 조직별 권한을 나눌 수 있다 |

포인트를 퍼블릭 체인에 올리면 사용자의 소비 패턴이 그대로 공개됩니다.
Fabric 원장에는 지갑 주소를 **해시(`hashDid`)해서** 올려 개인 식별을 한 번 더 끊었습니다.

**등급·한도 계산을 체인코드 안에서 합니다** (`calcGrade` · `getEarnRate` ·
`preSaleMonthlySubmitLimit`). 서버가 계산해서 넘기면 서버를 신뢰해야 하므로 원장의 의미가 없습니다.

**시각은 트랜잭션 타임스탬프**(`txNow`)를 씁니다. `time.Now()` 를 직접 부르면
피어마다 결과가 갈려 합의가 깨집니다.

## 8. 포인트 잔액을 저장하지 않는다

**선택** — `point_events` 에 적립·차감 이벤트만 쌓고, 잔액은 재계산.

**왜** — 잔액 컬럼과 이벤트 로그가 어긋나면 **어느 쪽이 맞는지 판단할 근거가 없습니다.**
이벤트만 두면 잔액은 언제나 이벤트로부터 유도됩니다.

**보너스** — mock Fabric 이 재시작으로 날아가도 포인트·멤버십이 MySQL 에서 복구됩니다.
이건 설계 의도의 부산물이었습니다.

**대가** — 이벤트가 많아지면 계산이 느려집니다. 지금 규모에서는 문제가 없고,
필요해지면 스냅샷 + 이후 이벤트 방식으로 바꿀 수 있습니다.

## 9. 프론트를 Node 가 아니라 Caddy 가 서빙한다

**선택** — Vite 빌드 결과를 Caddy 가 정적 서빙, `/api` 만 Node 로 프록시.

**왜** — 정적 파일을 Node 로 내보내면 API 요청과 같은 이벤트 루프를 씁니다.
Caddy 는 정적 서빙과 HTTPS 인증서 자동 발급·갱신을 함께 해결합니다.
설정 파일이 nginx 보다 짧아 배포 문서가 짧아집니다.

## 10. 최신 버전을 쓴 것들

여기부터는 "문제 때문"이 아니라 **선택**입니다. 정직하게 구분합니다.

| | 버전 | 이유 |
|---|---|---|
| React | 19 | 프로젝트 시작 시점의 최신. 특정 신기능 때문은 아님 |
| Vite | 6 | 개발 서버 시작이 빠르고 설정이 짧다 |
| Tailwind CSS | 4 | 화면 32개를 두 명이 만들면서 CSS 파일 관리를 없애려고 |
| TypeScript | 5.8 | 타입 검사 오류 0을 CI 게이트로 쓰기 위해 |
| Solidity | 0.8.28 | 0.8 대의 오버플로 기본 검사 |
| Node.js | 20 LTS | `node --test` 내장 러너를 쓰려고 — 테스트 프레임워크 의존성 0개 |

**`node --test` 를 고른 이유**는 적어 둘 만합니다. Jest·Mocha 를 넣지 않아
백엔드 의존성이 228개로 유지됩니다. 테스트를 돌리려고 무거운 설치를 하지 않아도 됩니다.

## 되돌릴 때 확인할 것

| 결정 | 되돌리려면 먼저 |
|---|---|
| 좌석 잠금을 DB에서 코드로 | 검사–삽입 틈을 어떻게 막을지 답이 있어야 함 |
| mock 기본값을 real 로 | 가스비 상한과 실패 시 롤백 경로가 있어야 함 |
| 포인트 잔액 컬럼 도입 | 이벤트와 어긋났을 때 어느 쪽이 맞는지 정해야 함 |
| 회전 QR 을 고정 QR 로 | 캡처 복제를 무엇으로 막을지 답이 있어야 함 |
